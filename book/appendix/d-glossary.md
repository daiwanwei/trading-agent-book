# 附錄 D：詞彙表

兩層各自服務不同的查閱需求。第一層是這本書自己造出來或賦予特定含義的詞，每條標出第一次被正式定義的章節；第二層從上游 `docs/en/glossary.md` 嚴選跟本書實際內容相關的領域術語，用繁體中文重新講一次，不逐條翻譯，並標出這個詞在書中真正出現、被拿來用的章節。兩層都不是索引——要查完整脈絡，還是得回到標出的那一節。

## 本書的詞彙

- **姿態** — Agent 對「今天願意讓多少風險上場」給出的判斷（`allow`／`restrict`／`cash-priority`），回答的是曝險該鬆該緊，不是任何一檔股票的買賣。（1.5 節）
- **姿態不是訊號** — 全書反覆回扣的定義：訊號說的是「買這一檔」，姿態說的是「今天願意讓多少風險上場」；`allow` 只是把後續動作的門解鎖，不等於下單指令。（1.5 節）
- **偵查隊** — 書中對候選生成類 skill 的統稱：VCP、CANSLIM、Stockbee 兩支動能篩子等同時派出去，各自用不同方法在同一片市場裡找目標，彼此不接力、不互相取代。（2.1 節）
- **候選≠訊號** — `swing-opportunity-daily.yaml` 的 `manual_review` 寫死的界線：偵查隊吐出多少候選都只是候選生成，真正的判斷留給第 7 步的週線人工複核。（2.1 節）
- **流派** — 書中對五套選股／存股方法論（Minervini、O'Neil、Stockbee、Kanchi、Shapiro）的統稱：彼此不互斥，該拿哪一套取決於市場現在的樣子，不是個人偏好。（2.4 節）
- **doc/code drift** — 文件寫的門檻跟程式碼實際執行的門檻悄悄脫鉤的現象；書中舉的實例是殖利率篩選門檻文件仍寫 3.5%，腳本早已改成 3.0%，文件沒有跟著更新。（2.4 節）
- **閘門** — workflow 裡標成 `decision_gate: true` 的步驟：不只是把證據攤開，而是要吐出一個明確判斷（如 `allow`、`TRADING_ALLOWED`、`GO`），下一步能不能走，繫在這個判斷上。（3.3 節）
- **fail-closed** — 輸入不完整或訊號互相矛盾時，系統預設「先擋下來」而非「假設沒事、繼續往下走」的設計哲學；姿態閘、斷路器、紀律閘門各自用不同機制落實同一個選擇。（3.3 節）
- **verdict** — 三道閘門各自算出的明確判斷（`exposure_decision`、`circuit_breaker_decision`、`pre_trade_discipline_decision`）；verdict 由程式算出、可稽核可重複，但真正攔下違規下單的從來不是程式碼，是願意照著 verdict 走的人。（3.3 節）
- **人與 Agent 的分工** — 全書貫穿的分工原則：Agent 負責把判斷做成可稽核、可重複的 verdict；人負責讀懂那個 verdict，並承擔按下按鈕之後的後果——這個分工不是妥協，是設計的核心。（3.4 節）
- **論點** — 一筆潛在交易被當成可否證假說管理的完整記錄，狀態機只有 `IDEA`、`ENTRY_READY`、`ACTIVE`、`PARTIALLY_CLOSED`、`CLOSED`、`INVALIDATED` 六種，只能前進不能倒退，且不到真實成交不轉 `ACTIVE`。（4.1 節）
- **隨機性** — `signal-postmortem` 歸因四選一（論點品質、執行、市場環境、隨機性）裡最容易被輕視的一項：承認一部分賺賠純粹是運氣，不歸功也不歸咎於任何判斷或執行，是誠實檢討的前提，不是逃避責任的萬用藉口。（4.2 節）

## 領域術語

- **派發日（Distribution Day）** — 大盤指數在比前一日更高的成交量下收跌、跌幅至少 0.2%，代表機構部位太大沒辦法一天出清，只能分批出脫；`market-top-detector` 與 `ibd-distribution-day-monitor` 各自用不同退場規則計數這種日子的累積量。（1.2 節）
- **FTD（Follow-Through Day）** — 修正之後的反彈嘗試進入 Day 4 到 Day 10 窗口時，若某天漲幅至少 1.25% 且成交量高於前一日，即視為機構開始回補的確認訊號；書中強調它是必要條件不是充分條件，約四分之三的 FTD 最終仍會失敗。（1.3 節）
- **期望值（Expectancy）** — 一套交易系統長期下來平均每筆賺賠多少；FTD 一節指出，即使單筆勝率不到五成，只要靠停損管理讓贏的部位賺得比輸的部位賠得多，整體期望值依然能是正的。（1.3 節）
- **VCP（波動收縮型態）** — Mark Minervini 提出的型態：股票在上升階段回檔，且每一次回檔深度都比前一次淺，代表賣壓逐漸被吸收、供給乾涸，突破機率隨之升高；`vcp-screener` 把它拆成趨勢模板、收縮品質等分量各自計分。（2.1 節）
- **CANSLIM** — William O'Neil 的成長股框架，七個字母分別對應當季獲利、年度獲利成長、新事物、供需、龍頭地位、法人認養與大盤方向；`canslim-screener` 把它量化成一個加權合成分數，市場方向這一項掛零就否決整體。（2.2 節）
- **動能（Momentum）** — 股價相對強弱能持續一段時間的傾向，Stockbee 流派用它找剛開始爆發或剛耗盡的股票：一支抓爆發、一支反過來抓衰竭後的反手，是同一種現象的兩種讀法。（2.3 節）
- **回檔（Pullback）** — 上升趨勢中的暫時性拉回，可能是進場機會，也可能是反轉的開端；`dividend-growth-pullback-screener` 主張回檔本身不是買進理由，得先靠股息成長率等基本面篩過一輪，`RSI` 只負責決定進場時機。（2.4 節）
- **RSI（相對強弱指標）** — 0 到 100 的動能震盪指標，數值越低代表近期跌勢越極端；書中舉奇異（GE）的反例提醒，基本面持續惡化時超賣訊號可能完全不可靠，讀數越極端，建議搭配的進場方式反而越保守。（2.4 節）
- **COT（Commitments of Traders）** — CFTC 每週五公布的期貨部位報告，內容是上週二收盤的建倉快照；`cot-contrarian-detector` 用它算擁擠度指數，但明文規定光憑擁擠度不能構成訊號，一定要疊上新聞驗證與價格行為確認。（2.5 節）
- **PEAD（財報後價格漂移）** — 股價在財報意外公布後，傾向朝原本驚訝的方向持續移動一段時間的現象；`pead-screener` 用財報跳空後出現紅 K 回檔、再收盤站上紅 K 高點，作為漂移趨勢恢復的進場條件。（2.6 節）
- **回撤（Drawdown）** — 帳戶或策略從先前高點下滑的幅度；部位計算一節用連續 10 筆虧損具體算給讀者看：每筆風險 1% 對應回撤 9.6%，5% 對應 40.1%，數字上的差距說明了為什麼風險比例要嚴格控管。（3.1 節）
- **ATR（真實波幅均值）** — 衡量一檔標的近期典型波動幅度的指標，涵蓋跳空缺口；部位計算一節用它取代固定金額停損，停損距離等於 ATR 乘上一個依持有週期調整的倍數。（3.1 節）
- **MAE（最大逆向偏移）** — 一筆部位持有期間，價格朝不利方向走到最遠的幅度；`trader-memory-core` 只在設定 FMP API key 時才會補上這個數字，用來檢視停損是不是設得過緊。（4.1 節）
- **MFE（最大順向偏移）** — 一筆部位持有期間，價格朝有利方向走到最遠的幅度；跟實際出場結果並排看，可以檢討出場是不是太早，但不能假設當時真的來得及在最高點賣出。（4.1 節）
